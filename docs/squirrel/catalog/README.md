# Script and data catalogue

Generated by `tools/squirrel/catalog.py <game> <data dir> [--sqtool build/sqtool.exe]`. Nothing here is game data: the
files hold paths, names, values, the developers' comments and their translations. Do not edit the generated files by
hand; edit the generator or the translation map and re-run it.

| file | what |
|---|---|
| `<game>_files.json` | one row per `.txt` under the data dir |
| `<game>_names.json` | constants, std moves/commands, shared state names, per-character moves/commands/HA6 pattern names |
| `<game>_catalog.md` | the same, as summary tables and per-character sections |
| `<game>_tr.json` | the translation map `{jp: en}` the generator reads (hand-maintained, machine first pass) |

Games: UNI2 1.42 and MBTL (Steam 25646393) are done. DFCI and UNIB use the same tool; they need their load-site rules in
`LOADSITES` (from `../RE_MBTL_LOAD.md`), a `<game>_tr.json` and the folder rules checked. Per-game layout lives in `GAMES`
in the generator: extra `kinds` rules (tried before `KINDS`), the cmd-table syntax, which folders are characters, whether
variant scripts are read, and the state-name list. UNI2 uses the defaults, and its output is byte-identical to the first
pass.

## Schema (schema 1)

`files[]`: `path` (relative, `/`), `kind` (`character script`, `shared battle script`, `data table`, `list or ini`,
`unknown`), `sub` (sc, cmd, mv, com, se_list, se_category, script, vector, battleinfo, boundeff, combase, ha6_stack,
talk, win_mes, battle_table, training_cmdlist, shader, bg, ...), `bytes`, `squirrel` (true when `sqtool compile`
compiles it; `compile_error` holds the first error otherwise), `load_site` (exe function and address, UNI2 1.42 IDB),
`timing` (`boot`, `boot (battle VM)`, `chara load`, `battle load`, `CSS`, `untraced`), `hot_reload` (`reloadstd`,
`reloadchara`, `reloadchara (rebuild only)`, `no`), `purpose` (English, from the kind and the traces), `header` (the
file's own first comment, translated).

Every translated string is `{"jp": original, "en": English or null, "tr": "machine" | "none" | null}`. `"machine"`
means not reviewed yet (corrections go into `<game>_tr.json`; a `"reviewed"` marker is not implemented yet). `"none"` means the source had no Japanese. `en: null` means no
translation in the map yet.

`names`:
- `consts[]`: `name`, `value` (source text), `file`, `line`, `comment` (trailing `//` comment, else the comment line
  above), `enum` for enum members. Covers every `const` in `script/*.txt` and `data/_combase.txt`.
- `std_moves[]` (`Std_MoveTable.X <-` in btl_StdMoveTbl) and per-character `moves[]` (`t.Mv_X <-` in the mv file):
  `name`, `line`, `template` (when the move is built by a `maketmpl_*` call), `movecode` (`def_MC*` flags the move
  sets), `ha6_patterns` (`code` = pattern code name from `SetPattern`/`SetVorpalPattern`/`GetPatternNum`/`pat=`, `num` =
  HA6 pattern number resolved through the character HA6 stack the way `GetPatternNum` does, first match wins, `ha6` =
  which file), `pattern_implied` (a `Mv_Skill_<X>` template whose pattern is code `<X>`, see RE_MBTL_LOAD.md "What a
  missing pattern does"), `commands` (cmd entries that start it, with their inputs).
- `std_commands[]` and per-character `commands[]`: `name`, `command` (inputs), `move` (UpdateTable name), `num`,
  `skilltype`.
- `states[]`: shared state names (stand, crouch, air, guard, shield, hitstun, knockdown, bound, throw, dash, counter,
  vorpal, veiloff, chainshift, exs) mapped by name to the engine constants (`../api/<game>_api.json`), the def_ consts,
  the `MvStatus` fields and the std moves. This is a name match, a starting point for review, not a traced mapping.
- `characters.<chrNNN>`: `num`, `short` (from `Def_ChrNo_<Short>`), `ha6_stack` (from `chrNNN_0.txt`), `moves`,
  `commands`, `patterns` (`id`, `ha6`, `code` PTCN, `title` PTT2, read with `tools/uni/ha6walk.py`), `sc_fields`
  (Battle_Status keys). `basedata_patterns` holds the shared BaseData.ha6 names once.
- MBTL only: `characters.<chr>.variants.<N>` for each `chrNNN_mv_N.txt` with N != 0 (story/boss variants; RE_MBTL_LOAD.md:
  "0 -> `_0`, 9 -> `_9` or `_N`, 999 -> no suffix"): `ha6_stack` (from `chrNNN_N.txt`), `moves`, `commands`, `sc_fields`,
  `patterns` (only the HA6 files that are not in the `_0` stack) and `new_moves` (moves the `_0` mv file does not have).
  Character keys are folder names, so `chr001solo` is its own entry (`num` 1).

Related standards this builds on rather than repeats: EF/IF labels `../../uni_re/labels/LABELS.md`, natives
`../api/<game>_api.json`, load order `../RE_MBTL_LOAD.md`, shared-file load sites and `reloadstd`
`fbmod/docs/TRAINING_CHARA_SWITCH.md` section 10.

## Consumers

- **fpan-im**: `hot_reload` tells the mod panel which command applies a changed file (`reloadstd` for script/* and the
  four boot tables, `reloadchara <chr>` for sc/cmd/mv, a restart otherwise). The names dictionary gives the panel
  readable move names (`Mv_*` + translated comment) and the command that starts each move.
- **Hantei-chan**: the pattern list can label patterns with the move(s) that set them (`ha6_patterns.num`), show
  translated PTT2 titles beside the JP, and the script editor can show the def_ const value/translation on hover.
  Paths and pattern numbers are stable keys; translations are display only.

## Known gaps (UNI2, first pass)

- Translations are a machine first pass; none are reviewed.
- Load sites for talk, win_mes, BattleTable, System and Shader files are not traced (`timing: untraced`); CSS/colour
  edit files are marked `CSS` from their folder, not from a trace.
- Move code is listed as the `def_MC*` flags a move sets; behaviour inside closures is not summarised.
- Pattern codes set through variables (`usepat`) or built strings are not resolved; `num: null` marks a code not found
  in the character HA6 stack (often a BaseData or effect pattern, or a computed name).
- `states` is a name match, not traced.

## Known gaps (MBTL 25646393, first pass)

- Translations: strings shared with UNI2 reuse `uni2_tr.json`; the rest are a machine first pass. None are reviewed.
- Load sites come from RE_MBTL_LOAD.md and TRAINING_CHARA_SWITCH.md section 10 (MBTL rows). `_combase_boss*.txt` is marked
  as loaded by the variant com files from their own `__dofile__` line, not from an exe trace. talk, win_mes, BattleTable,
  System, Shader, bg and the story NPC folders (`data/_talk/npcNNN`) are `untraced`; `_finish_list.txt` (load step 4) is not
  in this extract.
- The COM loader 0x606B60 has no name in the IDB yet.
- Pattern codes resolve first-match through the stack as the engine does; in MBTL `_temp.ha6` comes first and holds most
  move codes, so `ha6` is usually `_temp.ha6`, not `chrNNN.ha6`.
- The variant 999 stack (`chrNNN.txt`, no suffix) and `chr019_0_nobase.txt` are listed as files but not walked as a variant.
  HA6-only folders (`chr001solos456`, `chr001solos8`) are listed as files only.
- Story NPC scripts are classified, but their moves and commands are not read into `names`.
- `states` uses an MBTL word list (Shield, Moon Drive, Moon Skill, Rapid Beat, Last Arc, Blast, Krypt, Heat/Magic Circuit).
  It is a name match, not traced.
