# Script and data catalogue

Generated by `tools/squirrel/catalog.py <game> <data dir> [--sqtool build/sqtool.exe]`. Nothing here is game data: the
files hold paths, names, values, the developers' comments and their translations. Do not edit the generated files by
hand; edit the generator or the translation map and re-run it.

Run (UNI2): `sqtool check <data dir> --api docs/squirrel/api/uni2_api.json --game uni2 --trace-patterns trace.json` (Windows
sqtool, the path arguments as Windows paths), then `catalog.py uni2 <data dir> --trace trace.json`. Without `--trace` the
runtime fields are left out. `--legacy` writes the schema 1 monolithic files instead.

| file | what |
|---|---|
| `<game>_index.json` / `.md` | shared parts: files (kind, load site, timing, hot reload), consts, std moves/commands, states, BaseData patterns, character list with the per-character file names, stats |
| `<game>/chrNNN.json` / `.md` | one character: HA6 stack, moves (with resolved and runtime patterns), commands, effective HA6 patterns, sc fields |
| `<game>_tr.json` | the translation map `{jp: en}` the generator reads (hand-maintained, machine first pass) |
| `tools/squirrel/loadsites/<game>.json` | traced load sites (regex on path -> loader), generator input |
| `tools/squirrel/states/<game>.json` | traced state map, generator input |
| `tools/squirrel/annotations/*.json` | human-verified file purposes by folder (`purpose_src` names the source); they replace the generated `purpose` for every listed game |

JSON is minified; the `.md` files are the readable view. Hantei-chan needs only `<game>/chrNNN.json` for one character
(its `patterns` and `moves[].ha6_patterns` are self-contained); the index is only needed for consts and shared files.

Games: UNI2 1.42, MBTL (Steam 25646393), DFCI (`dfci+transmission`) and UNIB arcade (RingGame.exe sha cf96fd7f), all
schema 2 with the split output. Per-game layout lives in the generator: `GAMES` (extra `kinds` rules, cmd-table syntax,
which folders are characters, variant scripts, state-name list; MBTL) and `KINDS_GAME` / `CHARA_LAYOUT` (the
`data/<Name>_0/<Name>_0_{sc,cmd,mv}.txt` layout of DFCI and UNIB, support characters `data/<Name>_s_0/`; character number
from `Def_ChrNo_<Name>`, character key = folder name, so DFCI/UNIB files are `<game>/<Name>_0.json`). UNI2 uses the
defaults. The HA6 stack rule (`catalog_ext.resolve_ha6_stack`) is applied to every game, and to MBTL variant stacks.
Traced (`--trace`): UNI2, MBTL, DFCI. UNIB is static only.

## Schema (schema 2)

Changes from schema 1: `load_site` is an object, the output is split per character, HA6 patterns follow the engine's
stack rule, moves carry runtime patterns, states carry traced fields, and strings without Japanese are `{jp, tr:"none"}`
(`en` is the same as `jp` and is left out).

`files[]`: `path` (relative, `/`), `kind` (`character script`, `shared battle script`, `data table`, `list or ini`,
`unknown`), `sub` (sc, cmd, mv, com, se_list, se_category, script, vector, battleinfo, boundeff, combase, ha6_stack,
talk, win_mes, battle_table, training_cmdlist, shader, bg, ...), `bytes`, `squirrel` (true when `sqtool compile`
compiles it; `compile_error` holds the first error otherwise), `load_site` = `{fn, addr, when, consumer, traced}` (exe
loader, UNI2 1.42 IDB; `chain` holds the schema 1 call chain for the rules carried over; `traced:false` + `reason` when not
traced), `timing` (`boot`, `boot (battle VM)`, `chara load`, `battle load`, `CSS`, `talk scene`, `win demo`,
`replay save`, `scene`), `hot_reload` (`reloadstd`, `reloadchara`, `reloadchara (rebuild only)`, `no`), `purpose`,
`header` (the file's own first comment, translated).

### HA6 stack rule (`catalog_ext.resolve_ha6_stack`, shared by all games)

Traced in UNI2 1.42, same shape as MBTL: `CharaProject_LoadHa6DataFiles` 0x4C3B70 loads the `[DataFile]` list last to
first (`_temp.ha6, chrNNN.ha6, ../BaseData.HA6` loads BaseData, then chrNNN, then `_temp`). For each incoming pattern
`Han6_LoadPatternIntoSlot` 0x4C4800 stores it when the slot is empty or the pattern there has no frames, and drops it
when the pattern there has frames, unless that existing pattern has PFLG&1 (a template). Then
`Han6_MergeTemplatePattern_PFLG` 0x4C4D60 copies the incoming frames' layer/sprite fields into the template, which keeps
its own frame count, PTCN and flags. The flag is read on the pattern already in the slot, not on the incoming one. PTCN
lookup (`CharaObj_FindPatternByCodeName` 0x425480) returns the lowest slot whose effective pattern has the code. So
chrNNN.ha6 wins every number it defines, `_temp.ha6` only fills empty or frameless slots, and on a BaseData template
both of them merge layers in.

Per pattern: `pattern_source` (the effective file), `merged_from` (files merged into a PFLG&1 template, in load order),
`shadowed_in` (other stack files that define the number and are dropped). Move links (`ha6_patterns[]`) resolve `num`
through that lookup and carry `pattern_source`.

### Runtime patterns (`sqtool --trace-patterns`, `src/squirrel/move_trace.cpp`)

After each character loads, sqtool calls every `<CHR>_MoveTable` move's `Init` and `FrameUpdate` closure (`this` = the
move table, the character pushed) with the natives stubbed. It records every `BMvTbl.SetPattern` / `SetPattern_Reserve` /
`*VorpalPattern` argument and every `BMvTbl.JumpFrameID`. Engine objects the API has no class for (`value` returns,
`BMvCore.CCharaData`) read as an object whose fields are 0 and whose `push()`/`isdone()` return 0, meaning "no opponent".
Per move: `runtime_patterns[] {num, slot}`, `runtime_frame_id_jumps[]`, `runtime_errors[]`. A link the source could not
resolve gets `"resolved":"runtime"` with `num` (or `nums` when it sets more than one), or `effect` when the move sets no
pattern by design: a JumpFrameID move (UpdateFrameID template), `SetPattern(-1)`, or `def_TmplFlags_ChangeStatusOnly`.
Links still open carry `unresolved` with the reason.

`names` parts (index): `consts[]`, `std_moves[]`, `std_commands[]` as in schema 1. `states[]`: traced states carry
`traced:true`, `engine_consts`, `natives`, `mvstatus_fields`, `def_consts`, `object_flags`, `evidence` (IDB addresses);
the schema 1 name match is kept under `name_match`. Untraced states carry `traced:false`, `reason` and the name match.
`characters.<chrNNN>` (per-character file): `num`, `short`, `ha6_stack`, `moves` (`name`, `line`, `template`, `movecode`,
`ha6_patterns`, `pattern_implied`, `commands`, runtime fields), `commands`, `patterns`, `sc_fields`.

Every translated string is `{"jp": original, "en": English or null, "tr": "machine" | "none" | null}`. `"machine"`
means not reviewed yet (corrections go into `<game>_tr.json`; a `"reviewed"` marker is not implemented yet). `"none"` means the source had no Japanese. `en: null` means no
translation in the map yet.

`names`:
- `consts[]`: `name`, `value` (source text), `file`, `line`, `comment` (trailing `//` comment, else the comment line
  above), `enum` for enum members. Covers every `const` in `script/*.txt` and `data/_combase.txt`.
- `std_moves[]` (`Std_MoveTable.X <-` in btl_StdMoveTbl) and per-character `moves[]` (`t.Mv_X <-` in the mv file):
  `name`, `line`, `template` (when the move is built by a `maketmpl_*` call), `movecode` (`def_MC*` flags the move
  sets), `ha6_patterns` (`code` = pattern code name from `SetPattern`/`SetVorpalPattern`/`GetPatternNum`/`pat=`, `num` =
  HA6 pattern number resolved through the character HA6 stack the way `GetPatternNum` does, first match wins, `ha6` =
  which file), `pattern_implied` (a `Mv_Skill_<X>` template whose pattern is code `<X>`, see RE_MBTL_LOAD.md "What a
  missing pattern does"), `commands` (cmd entries that start it, with their inputs).
- `std_commands[]` and per-character `commands[]`: `name`, `command` (inputs), `move` (UpdateTable name), `num`,
  `skilltype`.
- `states[]`: shared state names (stand, crouch, air, guard, shield, hitstun, knockdown, bound, throw, dash, counter,
  vorpal, veiloff, chainshift, exs) mapped by name to the engine constants (`../api/<game>_api.json`), the def_ consts,
  the `MvStatus` fields and the std moves. This is a name match, a starting point for review, not a traced mapping.
- `characters.<chrNNN>`: `num`, `short` (from `Def_ChrNo_<Short>`), `ha6_stack` (from `chrNNN_0.txt`), `moves`,
  `commands`, `patterns` (`id`, `ha6`, `code` PTCN, `title` PTT2, read with `tools/uni/ha6walk.py`), `sc_fields`
  (Battle_Status keys). `basedata_patterns` holds the shared BaseData.ha6 names once.
- MBTL only: `characters.<chr>.variants.<N>` for each `chrNNN_mv_N.txt` with N != 0 (story/boss variants; RE_MBTL_LOAD.md:
  "0 -> `_0`, 9 -> `_9` or `_N`, 999 -> no suffix"): `ha6_stack` (from `chrNNN_N.txt`), `moves`, `commands`, `sc_fields`,
  `patterns` (only the HA6 files that are not in the `_0` stack) and `new_moves` (moves the `_0` mv file does not have).
  Character keys are folder names, so `chr001solo` is its own entry (`num` 1).

Related standards this builds on rather than repeats: EF/IF labels `../../uni_re/labels/LABELS.md`, natives
`../api/<game>_api.json`, load order `../RE_MBTL_LOAD.md`, shared-file load sites and `reloadstd`
`fbmod/docs/TRAINING_CHARA_SWITCH.md` section 10.

File purposes: `files[].purpose` is generated from the path rules unless an annotation matches. Annotated files also carry
`purpose_src` (now `"modder (BootySama, 2026-10-18)"` for `BattleTable`, `talk` and `win_mes` in all four games); prefer
it over the machine summary.

## Consumers

- **fpan-im**: `hot_reload` tells the mod panel which command applies a changed file (`reloadstd` for script/* and the
  four boot tables, `reloadchara <chr>` for sc/cmd/mv, a restart otherwise). The names dictionary gives the panel
  readable move names (`Mv_*` + translated comment) and the command that starts each move.
- **Hantei-chan**: the pattern list can label patterns with the move(s) that set them (`ha6_patterns.num`), show
  translated PTT2 titles beside the JP, and the script editor can show the def_ const value/translation on hover.
  Paths and pattern numbers are stable keys; translations are display only.

## Known gaps (UNI2, schema 2)

- Translations are a machine first pass; none are reviewed.
- Load sites: 522 of 626 files are traced. Not traced:
  - the per-character `se_list` / `se_category` and HA6 stack ini rules (from the load order, not an exe trace);
  - the `chr019solo*` / `chr020*` variant folders' HA6 ini and one bg/data file;
  - the System CSVs (Customize*, Gallery*, SingleMode*, Option* screens; not .txt, so not in the list);
  - talk `st_ending`/`st_bg`/`st_ev`/`st_face` and the talk CSVs (functions 0x8B9AF0, 0x8BB2D0, 0x8BF650, 0x8B8830,
    0x8C6C30, 0x8BA710 seen, not named);
  - two BattleTable string references outside any function (0x566DF3, 0x5676D9).
  See `loadsites/uni2.json` `untraced`.
- Runtime patterns: 26 links are still open. 25 moves set no pattern with stub engine state, because they pick it on a
  hit/frame/opponent branch the sandbox cannot reach. 1 move is not in the built move table. 28 std-move `Init_Std`
  calls fail on `BtlMvStd.SetGroundUkemiStatus`. It is not in `uni2_raw.json`, and the UNI2 1.42 IDB has no
  such string (only `SetUkemiTime`, `AirUkemi` and the like), so the exe registers no such native and it stays out of the API table.
- States: 9 of 16 are traced (stand, air, crouch, ground, guard, bound, counter, vorpal, dash). throw, shield, hitstun
  and knockdown have natives found but their fields are not decompiled. exs is traced only for the CPU AI getter. veiloff
  and chainshift have no native in the API table. Each carries its reason.
- Move code is listed as the `def_MC*` flags a move sets; behaviour inside closures is not summarised.
- Pattern codes set through variables (`usepat`) or built strings are not resolved; `num: null` marks a code not found
  in the character HA6 stack (often a BaseData or effect pattern, or a computed name).
- `states` is a name match, not traced.
