# Renderer shaders: inventory

Every GLSL program in the code today, where it lives, what it binds and how it is
blended. Written for the D3D9 port (docs/plans/render_d3d9/PLAN.md 5.2, P2 step 2),
which has to reproduce each program in HLSL.

The `*.glsl.vert` / `*.glsl.frag` files next to this README are the **exact text**
of the C++ raw string literals as of `render/d3d9` f8ae5b6 ("P0: move the window and
main loop to SDL3 with the GL backend"). They are generated by
[tools/hlsl/glsl_extract.py](../../tools/hlsl/glsl_extract.py) and the copies are
checked byte for byte by `tests/hlsl_glsl_identity_test.py` (ctest `glsl_identity`),
so they cannot drift from the code. P1 switches the C++ over to loading these files
and the test keeps the pair honest until then. The line numbers below are from that
commit; the extractor re-finds the strings by variable name, not by line.

The GLSL keeps a leading blank line and leading indentation because the raw string
starts right after `R"(`. That is intentional: the files are what the C++ passes to
`glShaderSource`.

## `simple` (src/render.cpp)

Vertex: `layout(location = 0) in vec3 Position; location = 1 in vec3 Color;`.

| Uniform | Type | Value |
|---|---|---|
| `ProjMtx` | mat4 | `projection * view` (`Render::SetMatrix`) |
| `Alpha` | float | `0.25` grid lines, `0.6` box line loop, `0.3` box fill |

Also sets `out vec4 Frag_Color = vec4(Color, Alpha)`; the fragment stage just writes
it. No samplers, no texture.

Draw calls: `vGeometry.Draw(geoParts[LINES], 0, GL_LINES)` for the grid,
`vGeometry.DrawQuads(GL_LINE_LOOP, ...)` then `GL_TRIANGLE_FAN` for the boxes
(hitboxes, PAT boxes). Attribute layout `F3F3` (pos3, colour3), src/vao.cpp:96.

Blend: whatever the caller left set; the grid and boxes are drawn after the state
reset to `SRC_ALPHA, ONE_MINUS_SRC_ALPHA` with `GL_FUNC_ADD` (src/render.cpp:445-446).
Depth test is on in the normal path, off in `Parts::Draw`.

## `textured` (src/render.cpp)

Vertex: `location 0 in vec2 Position; location 1 in vec2 UV; location 2 in vec4 Color`.
Attribute layout `F2F2` (pos2, uv2) plus a **constant** colour: attribute 2 is
disabled and supplied with `glVertexAttrib4fv(2, colorRgba)` (src/render.cpp:441, :500).

| Uniform | Type | Value |
|---|---|---|
| `ProjMtx` | mat4 | `projection * view` |
| `indexed` | int | `0` direct RGBA, `1` indexed point, `2` manual bilinear after palette lookup, `3` MBTL zoom>1 CG filter (`Render::ApplySpriteTextureMode`) |

| Sampler | Unit | Contents |
|---|---|---|
| `Texture` | 0 | CG texture: RGBA8, or 8-bit index in `.r` (`GL_R8`) |
| `Palette` | 1 | 256x1 RGBA current CG palette, point + clamp, re-uploaded with `glTexSubImage2D` per frame |

`indexed == 3` is the `CharaDrawBgColorBaseFilterBokashi` port: a 3x3 point-sampled
neighbourhood one texel apart, palette weighted .04/.06/.04, .06/.60/.06, .04/.06/.04
over the texels whose index is not 0, no renormalisation. `indexed == 2` is the manual
bilinear after the palette lookup. `palLookup` keeps `idx * (255/256) + 0.5/256`
exactly (src/render.cpp:89).

Blend (`Render::SetBlendingMode`, src/render.cpp:952):

| Mode | Equation | Func |
|---|---|---|
| `normal` | ADD | `SRC_ALPHA, ONE_MINUS_SRC_ALPHA` |
| `additive` | ADD | `SRC_ALPHA, ONE` |
| `subtractive` | `GL_FUNC_REVERSE_SUBTRACT` | `SRC_ALPHA, ONE` |

The normal case does not touch GL state at all (the comments say so): it relies on the
`SRC_ALPHA, ONE_MINUS_SRC_ALPHA` + ADD set at init (:262) and after every sprite
(:446, :505). The RHI has to make that explicit.

## `parts` (src/render.cpp, driven by src/parts/parts.cpp)

Vertex: `location 0 in vec3 Position; location 1 in vec4 UV; location 2 in vec4 Color`.
Layout `F3F4` (src/parts/parts.cpp): pos3 + 4 uv components (the flipped U/V pair, so
`UV.st` is the sample coordinate); attribute 2 is constant, set per part with
`glVertexAttrib4fv(2, newColor)` (src/parts/parts.cpp:743), where `newColor` is the
frame colour tint * PRCL palette entry * PRCB tint.

| Uniform | Type | Value |
|---|---|---|
| `ProjMtx` | mat4 | `pre * perspective * partView` (`Render::SetMatrixPersp`) |
| `addColor` | vec4 | PRSP specular, `addColor[0..3]` as floats (`setAddColor` callback) |

| Sampler | Unit | Contents |
|---|---|---|
| `Texture` | 0 | part texture, PRFL: exactly 1 = linear, else point (src/parts/parts.cpp:470) |

Fragment stage is the P3 reference for `PS_CharaPtDrawV`: `col = tex * Frag_Color; col += addColor`.

Blend per part (`ApplyPartBlend`, src/parts/parts.cpp:485, from PRAL):

| PRAL | Equation | Func |
|---|---|---|
| additive (`kBlendAdd`) | ADD | `SRC_ALPHA, ONE` |
| subtractive (`kBlendSub`) | `GL_FUNC_REVERSE_SUBTRACT` | `SRC_ALPHA, ONE` |
| normal (default, PRAL 3) | ADD | `SRC_ALPHA, ONE_MINUS_SRC_ALPHA` |

Depth test off, depth write off for the whole part loop (src/parts/parts.cpp:587-588),
restored only at the end of `Parts::Draw` (:906-908).

## `bg_object` (src/background/bg_renderer.cpp)

Vertex: `location 0 in vec3 aPos; location 1 in vec2 aUV; location 2 in vec4 aColor`
(interleaved 9 floats per vertex, src/background/bg_renderer.cpp:213).

| Uniform | Type | Value |
|---|---|---|
| `uProjView` | mat4 | `BuildProjView(clientW, clientH, camera.zoom, ...)` |
| `uAlpha` | float | frame alpha, `1.0` for the PAT branch (`glUniform1f(uAlphaLoc, ...)`, :611, :742, :791, :850, :904, :1271, :1476) |
| `uTint` | vec4 | per-draw diffuse (`tintRGB, tintRGB, tintRGB, 1.0` for stage PAT sprites) |
| `uAdd` | vec3 | per-draw specular (PAT part +68..70; `0,0,0` for plain sprites) |

| Sampler | Unit | Contents |
|---|---|---|
| `uTexture` | 0 | stage texture / sprite, direct RGBA (never indexed) |

Fragment stage models the D3D fixed function: `c.rgb * d.rgb + uAdd` with
`d = uTint * vCol`, alpha `c.a * uAlpha * d.a`.

Blend is per draw and set by the caller in the same file:
`SRC_ALPHA, ONE_MINUS_SRC_ALPHA` (:737, :792, :851, :905), `SRC_ALPHA, ONE` for
blend mode 2 (:735), `DST_COLOR, ZERO` for blend mode 3 = multiply (:736). Depth
test off, painter's order on the CPU. Draw is `glDrawArrays(GL_TRIANGLES, ...)` on a
dynamic 9-float VBO.

## `bg_blur` (src/background/bg_renderer.cpp, SakuraBloom)

Vertex: `location 0 in vec2 aPos`, a full-screen quad `{-1,-1 ... -1,-1}` (:991),
`vUV = aPos * 0.5 + 0.5`.

| Uniform | Type | Value |
|---|---|---|
| `uTex` | sampler2D unit 0 | the source bloom target |
| `uStep` | vec2 | `(±1.5 * zoom / W, -1.5 * zoom / H)`; GL's v is bottom-up so the game's +y diagonal is -v |
| `uMode` | int | `0` 9-tap blur, `1` plain copy |

9 taps at `uStep * {-4,-3,-2,-1,0,1,2,3,4}` with weights `.05 .075 .1 .15 .25 .15 .1 .075 .05`.
Blending is disabled (`glDisable(GL_BLEND)`) for the two blur passes, then the
composite run of the same program with `uMode = 1` uses `SRC_ALPHA, ONE`.

## `bg_heat` / `bg_heat_a` / `bg_heat_b` (src/background/bg_renderer.cpp, ApplyHeatBlur)

`bg_heat.glsl.vert` is the shared full-screen quad: `location 0 in vec2 aPos`,
`vUV = aPos * 0.5 + 0.5`, same as the blur vertex shader.

Pass A (`bg_heat_a`, technique `BgPointBlur`, sh_blur_1):

| Uniform | Type | Value |
|---|---|---|
| `uScene` | sampler2D unit 0 | `heatSceneTex`, a `glCopyTexSubImage2D` of the whole window |
| `uRect` | vec4 | game view inside the scene texture: `rx/clientW, ry/clientH, gw/clientW, gh/clientH` |
| `fPower` | float | `0.02 * fValue` |
| `fValue` | float | heat value, clamped 0..1 |
| `fColorHosei` | float | stage `stageColorVal` |

Writes MRT: `layout(location = 0) out vec4 oT0; location = 1 out vec4 oT1`.

Pass B (`bg_heat_b`, sh_blur_0):

| Uniform | Type | Value |
|---|---|---|
| `uT0` | sampler2D unit 0 | pass A output T0 |
| `uT1` | sampler2D unit 1 | pass A output T1 |
| `uMask` | sampler2D unit 2 | `EXFADE08.bmp` next to the game, or a white 1x1 |
| `uCenter` | vec2 | `(320 + 32*sin(ang)) / 640, (240 - 32*cos(ang)) / 480` |
| `fPower` | float | `0.02 * fValue` |
| `fValue` | float | heat value, clamped 0..1 |

Both passes are full-screen quads drawn with blending off; the composite goes into the
scene at the game view rectangle and restores `SRC_ALPHA, ONE_MINUS_SRC_ALPHA`.

## `s3d` (src/stage3d/s3d_view.cpp)

Vertex: `location 0 in vec3 aPos; location 1 in vec4 aColor; location 2 in vec2 aUv`
(offsets inside `s3d::Vertex`, set at :312-317).

| Uniform | Type | Value |
|---|---|---|
| `uWorld` | mat4 | per-sub-mesh world matrix (:434) |
| `uView` | mat4 | stage camera view (:415) |
| `uProj` | mat4 | stage camera projection (:416) |
| `uFlipV` | float | `s.flipV ? 1 : 0` (:423) |
| `uFogColor` | vec4 | `params.fogColor`, alpha forced to 0 when fog is off (:419) |
| `uFogCoord` | vec2 | `(fogEnd/span, -1/span)`, or `(1,0)` when the span is 0 (:420) |
| `uAlphaRef` | float | `0` (:421) |

| Sampler | Unit | Contents |
|---|---|---|
| `uTex` | 0 | model texture, or the 1x1 white texture when the sub-mesh has none |

The vertex stage passes `vFog = p.w` (a vertex shader for a 3D-space fog, not the
D3D9 fixed-function fog) and the fragment stage is `Diffuse_PS_Easy` from
`Shader\fbxshader.txt`: `tex * vertex colour`, unclamped fog lerp when
`uFogColor.a >= 0.001`, `discard` when `c.a <= uAlphaRef`.

Blend per sub-mesh (:436-437): additive `glBlendFuncSeparate(SRC_ALPHA, ONE, SRC_ALPHA, ONE)`,
otherwise `(SRC_ALPHA, ONE_MINUS_SRC_ALPHA, SRC_ALPHA, ONE)` - note alpha always
accumulates with `ONE`. Depth test `GL_LEQUAL` with depth write on. Culling per stage
params: `GL_BACK` with `GL_CCW` or `GL_CW`, or off. Draw is
`glDrawElements(GL_TRIANGLES, count, GL_UNSIGNED_INT, offset)`.

## `s3d_grade` (src/stage3d/s3d_view.cpp)

No attributes: the vertex stage synthesises a full-screen triangle from
`gl_VertexID` (`vec2 p = vec2((gl_VertexID & 1) * 2, (gl_VertexID >> 1) * 2)`,
`gl_Position = vec4(p * 2 - 1, 0, 1)`), drawn with `glDrawArrays(GL_TRIANGLES, 0, 3)`.

| Uniform | Type | Value |
|---|---|---|
| `uTex` | sampler2D unit 0 | `s.raw` stage target |
| `uLift` | float | `s.lift` |
| `uGain` | float | `s.contrast` |

Grade: `clamp(uLift + c * uGain, 0, 1)`, alpha 1. Blending, depth and culling are all
disabled for this pass (s3d_view.cpp:452-454). This is the composite of
`TecBgNoSpeculer`.



## HLSL ports

One file per program, `vs_3_0`/`ps_3_0`, entry points `VSMain`/`PSMain`
(the two heat passes are separate files because they have separate pixel entry
points, and each carries its own copy of the shared full-screen vertex stage).
The maths is the GLSL's, line for line, and the uniform names are the same, minus
the ones the RHI turns into vertex-shader constants:

| GLSL | HLSL | Why |
|---|---|---|
| `uniform mat4 ProjMtx` | `float4x4 ProjMtx` | same name |
| `uniform int indexed` | `int indexed` | same name (the HLSL spelling of "constant" needs no keyword) |
| `layout(location = 2) in vec4 Color` (textured) | `float4 g_color` | the C++ disables that attribute array and feeds it with `glVertexAttrib4fv(2, colorRgba)`, so it is a constant (PLAN.md 5.1) |
| the parts vertex colour (also attribute 2) | `float4 g_color` | same, set per part by `glVertexAttrib4fv(2, newColor)` |
| `textureSize(Texture, 0)` | `float2 g_texSize` | no `textureSize` in D3D9 |
| `texelFetch(Texture, t, 0)` | `tex2D(Texture, (float2(t) + 0.5) / g_texSize).r` | point sample at the texel centre |
| `vec2 uv.st` | `uv.xy` | HLSL has no `.st` swizzle |
| `mix(a, b, t)` | `lerp(a, b, t)` | same meaning |
| `gl_VertexID` triangle (s3d_grade) | three vertices `(0,0) (2,0) (0,2)` from a vertex buffer | vs_3_0 has no `gl_VertexID`; `Position = p * 2 - 1` is unchanged |
| `out vec4 FragColor` | `float4 PSMain(...) : COLOR` | |
| MRT `layout(location = 0/1) out` (bg_heat_a) | `float4 oT0 : COLOR0; float4 oT1 : COLOR1;` | |

| Program | HLSL file | Entry points |
|---|---|---|
| `simple` | `simple.hlsl` | `VSMain` `PSMain` |
| `textured` | `textured.hlsl` | `VSMain` `PSMain` |
| `parts` | `parts.hlsl` | `VSMain` `PSMain` |
| `bg_object` | `bg_object.hlsl` | `VSMain` `PSMain` |
| `bg_blur` | `bg_blur.hlsl` | `VSMain` `PSMain` |
| `bg_heat` pass A | `bg_heat_a.hlsl` | `VSMain` `PSMain` |
| `bg_heat` pass B | `bg_heat_b.hlsl` | `VSMain` `PSMain` |
| `s3d` | `s3d.hlsl` | `VSMain` `PSMain` |
| `s3d_grade` | `s3d_grade.hlsl` | `VSMain` `PSMain` |

So there is one HLSL file per program, except `bg_heat`: it is one GLSL program
whose two passes have different pixel shaders, so it becomes two files with the
shared vertex stage repeated in each.  Every file has exactly one `VSMain` and one
`PSMain` (18 entry points over the 9 files), which is what the runtime loader in
P2 will want; the split is by technique pass, not by stage.

`palLookup` keeps `idx * (255.0/256.0) + (0.5/256.0)` exactly, in every copy.
Samplers keep their GLSL names and take the same registers as the units in the
tables above (`Texture` = s0, `Palette` = s1, `uT0`/`uT1`/`uMask` = s0/s1/s2).
No shader applies a D3D9 half-pixel offset; that belongs to the projection
(PLAN.md 5.3, P2).

The one deliberate departure from a literal transcription is in `bg_heat_a`:
the GLSL's `for (int i = 0; i < 8; ++i) acc += S(...) * w[i]` is unrolled into
eight statements, because ps_3_0 forbids dynamically indexing a local array. The
eight weights are the ones written out in the GLSL, in the same order.

`tools/hlsl/hlslcompile.cpp` (ctest `hlsl_compile`) compiles every entry point
with `d3dcompiler_47.dll` (`D3DCOMPILE_OPTIMIZATION_LEVEL1`) and prints the
instruction count and the CTAB constant table (name, register set, register,
count). Every file must be `OK`; a failure there is an emission bug, not a game
file. `tests/hlsl_ref_test.cpp` (ctest `hlsl_ref`) then checks `textured` modes
0-3 and `parts` against scalar C++ copies of both the GLSL and the HLSL maths on
10,000 random inputs, to 1e-6.
